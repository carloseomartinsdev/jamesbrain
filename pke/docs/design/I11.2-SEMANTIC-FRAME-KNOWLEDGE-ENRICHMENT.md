## 1. Princípio central: conhecimento progressivo

```text
valid knowledge ≠ complete knowledge
missing information ≠ invalid knowledge
```

Três propriedades **não equivalentes**:

| Propriedade | Pergunta |
|-------------|----------|
| **Validity** | Pode persistir? |
| **Completeness** | Slots úteis preenchidos? |
| **Usefulness** | Valor para consultas/previsões futuras? |

Exemplo: *"Troquei o óleo do Corolla hoje."* — válido sem quilometragem, valor, oficina.

O PKE persiste o válido; perguntas complementares são **opcionais** e orientadas por valor.

## 2. SemanticFrame

Modelo experimental: `pke.design.semantic_frame.SemanticFrame`

Dimensões independentes e combináveis (não formulário fechado):

```text
actor, action, subject, object, participants,
time, place, manner, cause, purpose,
quantity, value, result, state_transition,
event_type, relation
```

Cada dimensão (`DimensionSlot`):

```text
known | unknown | missing | inferred | ambiguous | not_applicable | partially_known
```

Carrega epistemologia: `epistemic_status`, `evidence_source`, `confidence`, `broader_concepts`, `generalization_loss`.

---

## 3. Event × Action × State × Relation

**Não** existe regra `palavra → conceito`.

```text
surface expression + semantic role + entity types + relations
+ phrase context + session context + persistent knowledge
→ semantic concept candidate
```

| Primitive | Papel |
|-----------|-------|
| **Event** | Acontecimento/contexto episódico |
| **Action** | Algo executado — **não** obrigatoriamente subtipo de Event |
| **State** | Condição (quebrada, esgotada, atrasada) |
| **Relation** | Vínculo persistente entre entidades |

Coexistência numa `Occurrence`:

```text
event_type = maintenance
action = replace
object = clutch
subject = Corolla
time = today
resulting_state = clutch_replaced
```

**Instalação** — três leituras:

| Frase | Leitura |
|-------|---------|
| *"A instalação aconteceu ontem."* | `event_type = installation` |
| *"O técnico fez a instalação do ar."* | `event_type = service`, `action = install`, `object = AC` |
| *"As instalações da empresa são novas."* | **não** `event.installation` — leitura atributiva/estado |

Avaliar futuramente **polihierarquia** ou **semantic graph** vs árvore rígida.

---

## 4. Hierarquia dependente de contexto + SEMANTIC_INFORMATION_LOSS

Generalização só quando preserva distinções necessárias para consultas futuras.

| Classe | Significado |
|--------|-------------|
| **LOSSLESS** | Preserva distinções |
| **ACCEPTABLE_LOSS** | Ok para agregados |
| **DESTRUCTIVE** | Perde distinção crítica |

Exemplo destrutivo: `action.install` → `action.maintain` impede responder *"O ar já foi instalado?"*

Modelo futuro: conceito específico **+** broader concepts coexistindo — sem apagar o específico.

## 5–6. TemporalKnowledge parcial + tempo verbal como evidência

Modelo: `pke.design.temporal_knowledge.TemporalKnowledge`

Dimensões avaliadas: `absolute_time`, `relative_time`, `relation_to_now`, `aspect`, `recurrence`, `granularity`, `tense_evidence`, `uncertainty`, `unknown_reason`, `source`.

Distinções obrigatórias:

```text
missing | unknown | not_provided | forgotten | unresolved | inferred | known
```

| Frase | relation_to_now | aspect | absolute | unknown_reason |
|-------|-----------------|--------|----------|----------------|
| *"Comprei laranja."* | past | completed | unknown | not_provided |
| *"Vou comprar laranja."* | future | prospective | unknown | not_provided |
| *"Estou comprando laranja."* | present | ongoing | — | — |
| *"Costumo comprar aos sábados."* | habitual | habitual | — | recurrence |
| *"Fui ao cardiologista, mas não lembro quando."* | past | completed | unknown | **forgotten** |
| *"Fui ao cardiologista."* | past | completed | unknown | **not_provided** |

**Princípio:** Grammar may establish temporal relation without establishing calendar time.

## 7. Knowledge Enrichment

Fluxo futuro:

```text
NL → Interpretation → Semantic Resolution → Knowledge Candidate
→ Validity → Commit → Enrichment Analysis → Optional Clarification
```

Perguntas úteis **não bloqueiam** commit quando válido.

Enrichment ≠ Correction:

| | Enrichment | Correction |
|---|------------|------------|
| Efeito | Adiciona slot antes ausente | Altera informação considerada válida |
| Exemplo | +10.200 km depois | 180 → 186,50 |

---

## 8–9. InformationValueProfile + coverage map

Camadas além de essential/useful/optional:

```text
required_for_validity, information_value, future_utility,
query_utility, prediction_utility, uncertainty_reduction,
user_relevance, interaction_cost
```

Troca de óleo — mileage: `required_for_validity=low`, `future_utility=very_high`.

Coverage map exemplo (cenário A):

```text
WHAT/ ACTION / SUBJECT / WHEN → known
WHERE / VALUE / MILEAGE / PROVIDER → unknown
```

---

## 10. Clarification Policy

Não perguntar *"o que falta?"* — escolher por ganho.

```text
priority ≈ knowledge_gain × future_utility × uncertainty_reduction
         × contextual_relevance × user_relevance − interaction_friction
```

Política sugerida:

- máx. 1 pergunta prioritária por turno;
- não bloqueante se válido;
- evitar interrogatório;
- confirmar hipótese comportamental (*"Foi no São Luiz, como de costume?"*) sem promover a fato.

---

## 11. Context layers

Prioridade epistemológica (analítica, não congelada):

```text
explicit current statement > explicit session context
> confirmed persistent knowledge > behavioral pattern
> generic semantic prior
```

Relações de sessão: `same_occurrence`, `related_occurrence`, `same_place`, `same_temporal_context`, `same_subject`.

---

## 12–16. Behavioral Memory

`BehavioralPattern` — **≠ fato**. Condições + prediction + support + confidence.

`ContextualHypothesis` — estados: proposed → confirmed | rejected | superseded | expired.

Padrões condicionais: `vehicle=Corolla AND maintenance → Oficina João`.

Question response patterns (futuro): mileage alta probabilidade de resposta; oficina baixa.

---

## 17–18. Epistemic provenance + memórias

Separar `epistemic_status` de `evidence_source_kind`:

```text
status=inferred, source_kind=behavioral
status=confirmed, source_kind=user_confirmation
```

Seis categorias de memória: Ontological, Episodic, Semantic World, Behavioral, Derived, Epistemic Meta.

## Decisions ready to freeze

1. `valid knowledge ≠ complete knowledge`
2. `missing information ≠ invalid knowledge`
3. `behavioral pattern ≠ fact`
4. `contextual hypothesis ≠ fact until confirmed`
5. `surface expression ≠ canonical concept`
6. `concept ≠ word` (many-to-many mapping)
7. `generalization must not destroy semantic information` (DESTRUCTIVE forbidden as replacement)
8. `useful clarification should not block valid persistence`
9. `Event`, `Action`, `State`, `Relation` are distinct coexisting primitives
10. `grammar establishes temporal relation without requiring calendar time`
11. `forgotten ≠ not_provided` for temporal unknown_reason
12. `enrichment ≠ correction`
13. `CANONICAL_ALIAS ≠ TYPE_LEXEME ≠ INSTANCE_MENTION`
14. LLM cannot modify CORE automatically
15. EXTENDED grows via reviewed bootstrap, not silent LLM keys

## Decisions requiring experiment

- Forma exata de `TemporalKnowledge` no storage e no QueryEngine
- Representação física de `State` e histórico
- Relation temporal (`start_at`/`end_at`)
- Cálculo operacional de information value
- Same-occurrence resolution across messages
- Persistência de `ContextualHypothesis` vs ephemeral
- `BehavioralPattern` persistido vs projeção
- Polihierarquia vs semantic graph
- SemanticFrame na IR vs pós-resolução
- Materialização de State sem Event inventado
