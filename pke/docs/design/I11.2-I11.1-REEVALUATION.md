## 4. Dependem de resolução lexical/contextual

| Classificação I11.1 | needs | Correção proposta |
|---------------------|-------|-------------------|
| ALIAS_NEEDED | person, organization, appointment, attend, amount, vehicle→automobile | TYPE_LEXEME + CANONICAL_ALIAS + SEMANTIC_HINTS enrichment (I11.6) |
| Misclassified ALIAS | `entity.vehicle` → automobile | TYPE_LEXEME: "carro" é lexeme, "Corolla" é INSTANCE_MENTION |
| ROLE_CUE | cardiologista, dentista, técnico | não alias de person |

**Falhas semânticas com wire válido** (ex.: HOME_003 install→maintain only) são **GENERALIZABLE destrutiva**, não alias.

## 6. ALIAS_NEEDED mal classificados

## 7. GENERALIZABLE com perda semântica (DESTRUCTIVE)

| need | Generalização atual | Risco |
|------|---------------------|-------|
| `need.action.install` | → action.maintain | perde "foi instalado?" |
| `need.event.installation` | → event.maintenance | perde distinção instalação vs reparo |
| `need.action.cancel` | → (nenhum) | ok como NEW |
| `need.action.lend` | → action.pay | **DESTRUCTIVE** — direção credor/devedor |
| `need.event.anomaly` | → event.maintenance | **DESTRUCTIVE** — barulho ≠ manutenção feita |
| `need.entity.appliance` | → entity.vehicle | **DESTRUCTIVE** — geladeira ≠ automóvel |

**Regra I11.2:** broader concept coexiste; não substitui.

## 8. Falhas de expressividade do IR (não LLM)

| Área | Evidência |
|------|-----------|
| State primitive ausente | 3 REPRESENTATION_GAP state |
| Relation types insuficientes | 2 REPRESENTATION_GAP relation |
| attribute.quantity ausente | SHOP_001 |
| Temporal partial não modelável | HEALTH_002, travel, "comprei" |
| No relation direction | emprestou 500 |
| No enrichment slot | wire one-shot |

**Canonical failures (38.5%)** misturam: keys desconhecidas (LLM) + schema sem slot.

---

## 9. Realmente erros do LLM

- JSON inválido / keys inventadas (`action.install` rejeitada pelo wire quando não no catalog)
- Inventar `hoje` em D2 (semantic, não ontology)
- `event.intent` como fallback genérico frequente no baseline
- Confundir obligation com purchase

**Separar:** provider stochasticity ≠ ontology gap ≠ IR gap.

---

## 10. Exigem mudança do benchmark?

| Situação | Mudança? |
|----------|----------|
| State/Relation gaps | **Não** — benchmark correto ao exigir REPRESENTATION_GAP hoje |
| ALIAS_NEEDED como pass | **Sim, futuro** — após I11.6, invariantes podem aceitar TYPE_LEXEME resolution |
| GENERALIZABLE como pass | **Revisar** — alguns casos devem falhar até broader+specific coexist |
| atemporal HEALTH_002 | **Não** — expects clarification per ADR 0014; benchmark ok |

**Holdout permanece congelado** até revisão pós-implementação.

