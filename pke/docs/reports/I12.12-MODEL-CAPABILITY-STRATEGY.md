## Engine v1 reliability definition (§6)

```text
Engine v1 reliability ≠ 100% automatic useful capture

Engine v1 reliability =
  safe autonomous execution when sufficient
  + safe clarification when a detectable, user-answerable gap blocks execution
  + safe abstention when the gap cannot be recovered without guessing
```

## Strategy matrix (§115)

| Outcome | Semantic status | Materialization | Clarification | User-facing meaning |
|---------|-----------------|-----------------|---------------|---------------------|
| AUTO_EXECUTE | Valid + complete | Commit all ready | No | Knowledge recorded |
| PARTIAL_EXECUTE | Mixed ready + partial/incomplete | Commit ready only (COMMIT_VALID_INDEPENDENTLY) | Not blocking ready | Partial knowledge + optional later gap |
| CLARIFY | Valid + detectable gap; zero ready | None yet | One structured request | Ask for missing slot |
| SAFE_ABSTAIN | Valid but not usefully recoverable | None | No | Decline without guessing |
| INVALID | Unparseable / contract-invalid | None | Never | Error / unsupported |

Authority: `decide_capability` ← `assess_execution_readiness`.

## How reassessment works without a second Interpreter (§30–§34)

```text
pending SemanticProposal (frozen copy)
+ user answer scoped to missing_slot / expected_answer_kind
→ apply_clarification_evidence (deterministic field fill)
→ resolve_proposal + assess_execution_readiness + decide_capability
→ materialize only if now AUTO/PARTIAL
```

Forbidden: `original_raw + answer → unrestricted Interpreter`.

**Product debt:** `ConversationOrchestrator.answer_clarification` currently concatenates and re-runs the Engine on a merged utterance. That is **not** the Engine strategy and must be replaced in the next increment.
